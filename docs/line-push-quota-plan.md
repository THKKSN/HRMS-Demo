## 1. โควตาหายไปไหน

### 1.1 กติกาการนับของ LINE

| | นับโควตาไหม |
|---|---|
| **push / multicast / broadcast** | ✅ นับ **ต่อผู้รับ 1 คน ต่อ message object 1 ชิ้น** |
| **reply** (ตอบกลับด้วย `replyToken`) | ❌ **ฟรี ไม่จำกัด** |

โค้ดนี้ส่ง message object ชิ้นเดียวต่อ push เสมอ ([`PushAsync`](../apps/api/Hrms.Infrastructure/Services/LineMessagingService.cs#L154)) ฉะนั้น **จำนวนผู้รับ = จำนวนข้อความที่ถูกหัก** ตรง ๆ ไม่มีตัวคูณซ่อน

> รอบบิลรีเซ็ตต้นเดือน — ยืนยันวันจริงที่ LINE OA Manager ก่อนวางแผนรอบถัดไป

### 1.2 ใครกิน push บ้าง (เฉพาะที่รันจริงบน production)

| ผู้ส่ง | ทริกเกอร์ | ผู้รับต่อครั้ง |
|---|---|---|
| [`NotificationDeliveryJob`](../apps/api/Hrms.Infrastructure/Jobs/NotificationDeliveryJob.cs) | ทุกนาที ดูดจาก outbox | 1 แถว = 1 ข้อความ |
| [`LeaveNotificationJob`](../apps/api/Hrms.Infrastructure/Jobs/LeaveNotificationJob.cs#L39-L49) | ยื่น/อนุมัติใบลา | **หัวหน้าทั้งบริษัท** แล้ว **HR ทั้งบริษัท** |
| [`ExternalRepairSyncDeliveryJob`](../apps/api/Hrms.Infrastructure/Jobs/ExternalRepairSyncDeliveryJob.cs) | ทุกนาที | 1 แถว = 1 ข้อความ |
| [`RequestOtpHandler`](../apps/api/Hrms.Application/Features/Auth/RequestOtp/RequestOtpHandler.cs#L47) | ผูกบัญชีครั้งแรก | 1 |
| [`HandleCheckQuotaCommand`](../apps/api/Hrms.Application/Features/LineWebhook/Commands/HandleCheckQuotaCommand.cs#L118-L127) | ตอบไม่ทัน `replyToken` | 1 (เคสหลุดเท่านั้น) |

🔎 **[`DailyAttendanceReportJob`](../apps/api/Hrms.Infrastructure/Jobs/DailyAttendanceReportJob.cs) ไม่ได้รันบน production** — ลงทะเบียนอยู่ใน
[`RegisterDevelopmentJobs()`](../apps/api/Hrms.Infrastructure/Jobs/RecurringJobRegistrar.cs#L7-L14) เท่านั้น ส่วน `RegisterProductionJobs()` ไม่มี
ต้องเคาะว่า **ตั้งใจปิด หรือลืมย้าย** (ดู D3) ถ้าเปิดขึ้นมาคือค่าใช้จ่ายคงที่ทุกวันทำการ:

```
ผู้บริหารต่อบริษัท × จำนวนบริษัท × 22 วันทำการ
เช่น 3 คน × 2 บริษัท × 22 = 132 ข้อความ/เดือน = 44% ของโควตาทั้งก้อน
```

### 1.3 เลขที่ทำให้เห็นภาพ

**ใบแจ้งเรื่อง 1 ใบ** ไล่ตั้งแต่เปิดจนปิดผ่าน event ราว 5 จังหวะ × ผู้รับ 2–3 คน ≈ **10–15 ข้อความ**

> **300 ข้อความ/เดือน ≈ ใบแจ้งเรื่อง 20–30 ใบ** — ยังไม่นับใบลาเลยสักใบ

**ใบลา 1 ใบ** = หัวหน้าทุกคนในบริษัท + HR ทุกคนในบริษัท + ผู้ยื่น 1
ถ้ามีหัวหน้า 4 HR 2 → **7 ข้อความต่อใบลา 1 ใบ ทั้งที่มีคนกดอนุมัติจริงแค่ 1 คน**

## 2. สิ่งที่เจอจากการสำรวจโค้ด

### 2.1 🔴 ใบลาหายเงียบ ไม่มีแม้แต่บรรทัด log

[`LeaveNotificationJob.cs:83`](../apps/api/Hrms.Infrastructure/Jobs/LeaveNotificationJob.cs#L83) · [`:125`](../apps/api/Hrms.Infrastructure/Jobs/LeaveNotificationJob.cs#L125) · [`DailyAttendanceReportJob.cs:96`](../apps/api/Hrms.Infrastructure/Jobs/DailyAttendanceReportJob.cs#L96)

```csharp
try { await line.PushFlexMessageAsync(recipient.LineUserId, altText, card); }
catch { /* ไม่ให้ job ล้มเหลวถ้า push คนใดคนหนึ่งไม่ได้ */ }
```

เจตนาถูก (คนเดียวพังไม่ควรล้มทั้ง job) แต่ `catch` เปล่าแปลว่า **ไม่มีทั้ง log ไม่มีทั้งแถวใน DB**
ช่วงที่โควตาเต็ม ใบลาที่พนักงานยื่นไม่ถึงผู้อนุมัติเลย **และไม่มีใครรู้ว่าหายไปกี่ใบ**

### 2.2 🟠 429 เผาโควตา retry จนตกขอบ แล้วไม่กลับมาเอง

[`NotificationDeliveryJob.cs:91-105`](../apps/api/Hrms.Infrastructure/Jobs/NotificationDeliveryJob.cs#L91-L105) — 429 ตกเข้า `catch` รวมกับ error อื่น
ถอยหลัง 1→2→4→8 นาที ครบ 5 ครั้งเป็น `DeadLetter` + `NextAttemptAt = null`

**~15 นาทีหลังโควตาหมด ทุกอย่างที่เข้าคิวจะตายถาวร** และ query ของ job หยิบเฉพาะ `Pending`/`Failed`
พอโควตาคืนต้นเดือนมันจะ**ไม่ไหลเอง** ต้องไปกดทีละแถวที่ [settings/notification-deliveries](../apps/admin-web/app/(main)/settings/notification-deliveries/page.tsx)
เพราะ [`RetryNotificationDeliveryCommand`](../apps/api/Hrms.Application/Features/NotificationDeliveries/Commands/RetryNotificationDeliveryCommand.cs#L10) รับ `Guid` เดียว ไม่มี bulk

> 429 ของ LINE ไม่ได้แปลว่าข้อความเสีย แปลว่า "ยังไม่ถึงคิว" — จับรวมกับ payload พังจึงผิดตั้งแต่ต้น

### 2.3 🟠 ไม่มีใครมองเห็นโควตาจนกว่าจะเต็ม

ไม่มีโค้ดเรียก `GET /v2/bot/message/quota` หรือ `/consumption` เลย — รู้ว่าเต็มก็ตอนส่งไม่ออกแล้ว
ไม่มีข้อมูลย้อนหลังว่าเดือนที่ผ่านมาหมดไปกับ ticket กี่ % ใบลากี่ % จึงยัง**เดาไม่ได้ว่าต้องซื้อแพ็กเกจเท่าไหร่**

### 2.4 🟢 มีคันโยกที่ปรับได้โดยไม่ต้อง deploy อยู่แล้ว

[`QueueForTeamAsync`](../apps/api/Hrms.Application/Features/Tickets/TicketCommandSupport.cs#L139-L161) อ่าน `Ticket:TeamNotificationEvents` จาก appsettings —
event ที่ไม่อยู่ในลิสต์จะส่งถึง**ผู้รับผิดชอบหลักคนเดียว** ไม่กระจายทั้งทีม

appsettings บน server แก้มือได้ (ไม่ถูกทับตอน deploy) → **ตัดลิสต์นี้ให้สั้นลงคือการลดโควตาที่ทำได้วันนี้เลย**

## 5. นอกขอบเขต

- **เปลี่ยนไปใช้ช่องทางอื่นแทน LINE** (อีเมล/SMS/push ของ LIFF) — คนละเรื่อง ค่อยคุยหลังมีเลขจาก Q0.3
- **multicast/broadcast** — LINE นับต่อผู้รับเหมือน push ไม่ได้ช่วยลดโควตา ช่วยแค่ลดจำนวน HTTP request
- **ย้ายข้อความไปเป็น reply ให้หมด** — reply ต้องมี `replyToken` จากที่ผู้ใช้ทักเข้ามาก่อน ใช้กับการแจ้งเตือนที่ระบบเป็นฝ่ายเริ่มไม่ได้
